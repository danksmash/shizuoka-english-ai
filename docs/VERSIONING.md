# アプリVersion・Build・更新履歴

## 表示ルール

- 児童用：メイン画面最下部の既存説明文の後ろにだけ `AI留学生えいご対話 Version x.y.z Build YYYY-MM-DD` を表示する。
- 児童用の対話画面・振り返り画面には表示しない。
- 教師用：ログイン後の「授業・学級状況」メイン画面の最下部にだけ、小さく薄くVersion/Buildを表示する。
- 研究者用：ログイン後の「研究データ概要」メイン画面の最下部にだけ、小さく薄くVersion/Buildを表示する。
- 教師用・研究者用の最上部ナビには「バージョン情報」ボタンを常設し、別画面で更新履歴を表示する。

## 自動更新

Version 1.0.3から自動管理を開始する。基準コミット以後の意味のあるアプリ修正コミットを順番に数え、`1.0.3`、`1.0.4`、`1.0.5` のようにpatch番号を自動更新する。

`chore:`、`ci:`、`docs:`、`test:`、`build:`、一時ファイルやMerge commitはVersion増分の対象外とする。通常の `feat:`、`fix:`、`refactor:` 等、および一般的な修正コミットは対象とする。

Build日はビルド実行時の日本時間（Asia/Tokyo）の日付を自動使用する。更新履歴は対象コミットの件名を簡潔な変更内容として自動生成し、最新Versionから順に表示する。

GitHub Actionsでは完全なGit履歴を取得し、GitHub PagesとCloud Runのどちらも同じVersion算出ルールを利用する。
