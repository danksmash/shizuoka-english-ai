# 学習履歴・研究データのアクセス／保存／復元設計

## 分離原則

- 児童は学習コードだけを使用する。学習コードそのものはセッション文書へ保存しない。
- サーバーは学習コードをHMAC-SHA256で索引化して、内部`studentId`と研究用`researchId`へ解決する。
- 児童用APIは本人の学習コードに対応する履歴だけを返す。
- 研究者用管理画面は児童画面からリンクしない別URL `/management` とする。
- 教師用管理画面は設けず、研究者だけが匿名化された研究データを取得できる。
- 管理認証CookieはHttpOnly / Secure / SameSite=Strict、8時間で失効する。

## 保存データ

完全セッションには、内部ID、研究ID、セッションID、AI留学生ID、話題、設定時間、実時間、開始終了時刻、通算回数、当日回数、ターン数、児童発話語数、語彙、氏名・学校名・学習者ID等も保存前に除去した研究用匿名化対話履歴、児童の振り返りを保存する。

統計値はクライアント申告値を信用せず、サーバーが履歴と時刻から再計算する。

## 保存期間

既定のセッション保存期間は1095日（3年）。Cloud Run環境変数`SESSION_RETENTION_DAYS`で30〜3650日の範囲に変更できる。各文書に`retentionExpiresAt`を保存し、Firestore TTLポリシーをこのフィールドへ設定する前提とする。研究倫理審査・共同研究契約で別期間が決まった場合は、その値を優先する。

## バックアップ

- 本番Firestoreは日次スケジュールバックアップを推奨する。
- バックアップ保持は14週間以内で設定する。
- 必要に応じてPITRを併用する。
- 復元試験は、本番`(default)`を上書きせず、別の一時データベースへ復元して件数・代表文書・匿名化Exportを照合する。
- 復元試験完了後、一時データベースを削除する。

## 秘密情報

`LEARNING_CODE_PEPPER`、`MANAGEMENT_SESSION_SECRET`、`MANAGEMENT_ACCOUNTS_JSON`はGitHubへ保存しない。Google Cloud / GitHub Actionsの秘密情報として管理する。
